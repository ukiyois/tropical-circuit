## 1. The retraction, which is mine to make

`docs/strengthening-audit-2026-09-20.md` section 10 proposed proving
`MC(P_PERM) = 2^{Omega(n)}`, and Section 7 of the manuscript now states it as an
open problem. **It is false.** JSS record, verbatim:

> "if a tropical polynomial `P` can be computed by a `(min,+,-)` circuit of size
> `s`, then `P` can be computed by a `(min,+,-)` circuit of size `2s` with at
> most one subtraction gate as the output gate. Namely, we can move subtraction
> `(-)` gates towards the output gate using the equations
> `min{a-b,c} = min{a,b+c}-b`, `(a-b)+c = (a+c)-b` and `(a-b)-c = a-(b+c)`. ...
> Thus, `(min,+,-)` circuits are essentially of the form
> `Phi(x) = Phi_1(x) - Phi_2(x)`, where `Phi_1` and `Phi_2` are `(min,+)`
> circuits."

I verified the identity `min(a-b,c) = min(a,b+c)-b` and, independently, a
decomposition that is manifestly linear on DAGs with fan-out. Carry every gate
as a pair `g = g^+ - g^-`:

```
input x        x^+ = x,                          x^- = 0
constant 0     0^+ = 0,                          0^- = 0
a + b          (a^+ + b^+)                     - (a^- + b^-)
a - b          (a^+ + b^-)                     - (a^- + b^+)
min(a,b)       min(a^+ + b^-,  b^+ + a^-)      - (a^- + b^-)
max(a,b)       max(a^+ + b^-,  b^+ + a^-)      - (a^- + b^-)
```

Each line is a direct identity; the `min` line is
`min(a,b) = min(a + (a^-+b^-) - a^-, b + (a^-+b^-) - b^-) - (a^-+b^-)`. Every
original gate becomes `O(1)` new gates and each `g^+`, `g^-` is shared by all
successors, so the size is `O(s)` on a DAG, not only on a formula.

**Consequence.** Theorem 1.1 gives a `(max,+,-,0)` circuit of size `O(n^8)` for
`Assign_n`, hence

```
Assign_n = Phi_1 - Phi_2 ,   Phi_1, Phi_2 pure (max,+,0),   |Phi_1|+|Phi_2| = O(n^8).
```

In the constant-`0` model a pure circuit computes a support function, so
`Phi_1 = h_A`, `Phi_2 = h_B` and `h_{P_PERM} = h_A - h_B` forces `A = P + B`.
Therefore `MC(P_PERM) = O(n^8)`, and the problem I stated has the answer no.

**The replacement statement is better.** Combining with the reciprocal-input
theorem of the same paper, which I verified earlier as
`size_without <= size_with^2`:

```
(min,+)                                exponential for Assign_n
(min,+) with -x_e available as inputs  exponential for Assign_n
(min,+) with one subtraction at the output   O(n^8)
```

So the operative distinction is not internal against output. It is **input
against everything else**: pre-supplying signs is exponentially weak, and a
single cancellation at the very end is already the full power of `(min,+,-)`.
The current Section 5 sentence about "the single internal scalar `-1`" is
therefore mis-aimed and must be rewritten.

## 2. JSS Problem 4: answered by Theorem 1.1

> **Problem 4.** "Can the tropical permanent `Per_n` be computed by a
> `(min,+,-)` circuit of polynomial size?"

`Per_n(x) = min_M sum_{e in M} x_e` over perfect matchings of `K_{n,n}` is
`Assign_n`. Basis conversion is free: `max(x,y) = 0 - min(0-x, 0-y)` costs four
gates and the reverse likewise, so `(max,+,-,0)` and `(min,+,-,0)` circuit sizes
agree up to a factor of four. Theorem 1.1 answers **yes**, at `O(n^8)`.

Our model uses only the constant `0` while JSS allow nonnegative real constants,
so our circuit is in the smaller model and the answer is if anything stronger.

## 3. JSS Problem 3: answered, and the gap is exponential

> **Problem 3.** "Can the `(min,+,max)/(min,+,-)` gap be super-polynomial?"

JSS supply the lower-bound half themselves:

> **Proposition 2.** "If a minimization problem can be solved by a
> `(min,+,max)` circuit of size `s`, then the Boolean version of this problem can
> be computed by a monotone Boolean `(and,or)` circuit of size `s`."

and deduce **Corollary 5**, `n^{Omega(log n)}` for `Per_n`, from Razborov.

That corollary now upgrades for free. Cavalar, Göös, Riazanov, Sofronova and
Sokolov, *Monotone Circuit Complexity of Matching*, STOC 2026, state verbatim:

> "He considered the bipartite perfect matching function
> `MATCH: {0,1}^{n^2} -> {0,1}` that takes as input a bipartite graph,
> represented by its adjacency matrix `x in {0,1}^{n x n}` ... Razborov showed
> that it requires monotone circuits of size `n^{Omega(log n)}`. ...
> **Theorem 1.** `MATCH` requires monotone circuits of size at least
> `2^{n^{1/3-o(1)}}`."

Bipartite, `n` per side, `n^2` input bits, monotone circuit size. Exactly the
function in JSS Proposition 2. Hence

```
Size_{min,+,max}(Per_n) >= 2^{n^{1/3-o(1)}}      vs      Size_{min,+,-}(Per_n) = O(n^8).
```

Answered **yes**, with an explicit exponential against polynomial separation
rather than merely super-polynomial. The only new ingredient of ours is the
upper bound; the rest is two quoted results meeting.

## 4. JSS Problem 5: answered by the compiler

> **Problem 5.** "Can the `(min,max)/(min,+,-)` gap be super-polynomial? That
> is, can subtractions help for bottleneck problems?"

Take the widest perfect matching, a standard bottleneck problem:

```
Lambda_n(x) = max_{M in PM(K_{n,n})} min_{e in M} x_e .
```

**Upper bound, from our own compiler.** `Lambda_n = C_F` with
`F(S) = MATCH(E \ S)`, and `F(E) = MATCH(empty) = 0`, so
Definition 3.1 applies. With `m = n^2` and a Boolean circuit of size
`s = O(n^2 m)` for `F`, Theorem 3.7 gives

```
Size_{max,+,-}(Lambda_n) = O(ms + m^2 + m log^2 m) = O(n^6) ,
```

and four times that in the `(min,+,-)` basis.

**Lower bound, from an exact equivalence.** For monotone `f` with
`f(empty)=0`, `f([m])=1`, the Lovász extension is the max-min lattice
polynomial `f^(x) = max_{A: f(A)=1} min_{i in A} x_i`, since for such `f` the
integrand `1[f({i : x_i >= t}) = 1]` is the indicator of `t <= f^(x)`. Given a
monotone Boolean circuit `C` for `f`, replace `and` by `min` and `or` by `max`;
induction on gates gives

```
1[ C^lat(x) >= t ] = C( 1[x_1 >= t], ..., 1[x_m >= t] )   for every t,
```

hence `C^lat = f^`. Conversely a `(min,max)` circuit restricted to `{0,1}^m` is a
monotone Boolean circuit for `f`. Therefore

```
LatSize(f^) = MonBoolSize(f),        LatDepth(f^) = MonBoolDepth(f),
```

as equalities, not reductions. With `f = MATCH` and the CGRSS bound,

```
Size_{min,max}(Lambda_n) >= 2^{n^{1/3-o(1)}}      vs      Size_{min,+,-}(Lambda_n) = O(n^6).
```

Answered **yes**. Note that Razborov's classical `n^{Omega(log n)}` already
answers Problem 5 super-polynomially, so this half does not depend on the
three-month-old citation; CGRSS only sharpens it to exponential.

**Depth separation, free.** CGRSS record that Raz and Wigderson proved bipartite
matching requires monotone formulas of size `2^{Omega(n)}`, so
`MonBoolDepth(MATCH) = Omega(n)`, and the depth equality gives
`Depth_{min,max}(Lambda_n) = Omega(n)`. With the `NC` observer of CGGRT the
compiler gives `Depth_{max,+,-}(Lambda_n) = polylog(n)`. This needs nothing from
the assignment schedule.

## 5. JSS Problem 6: a barrier, correctly scoped

> **Problem 6.** "Prove any nontrivial lower bound on the size of `(min,+,-)`
> circuits."

JSS add that Problem 6 "may be an even harder challenge than Problem 3". The
compiler says why, on the class it covers. From
`STropSize(f^) = O(m * BoolSize(f) + m^2 + m log^2 m)`:

```
BoolSize(f) >= ( STropSize(f^) - O(m^2 + m log^2 m) ) / O(m) .
```

So a super-polynomial `(min,+,-)` lower bound for a Lovász extension of an
explicit set function yields a super-polynomial **general** Boolean circuit lower
bound for that function.

The converse containment holds too and is worth stating for the equivalence.
On inputs `x in {0,1}^m` with only the constant `0`, every wire of a signed
circuit of size `s` is an integer of absolute value at most `2^s`, since each
gate at most doubles the magnitude, so `O(s)` bits suffice. Simulating the `s`
gates with Boolean adders, subtractors and comparators costs `O(s^2)` gates,
and `f^(1_S) = f(S)`. Hence `BoolSize(f) <= poly(STropSize(f^))`, and the two
measures are polynomially equivalent on this class.

**Scope, which matters.** The barrier applies to targets that *are* Lovász
extensions. `Per_n` is not one, by section 6 below, so the barrier does not
obstruct a lower bound for `Per_n` itself. What it does obstruct is
`Lambda_n` and every other braid-compatible bottleneck target, which is exactly
where the reader would look next after Problem 5.

## 6. `Assign_n` is not a Lovász extension, and neither are shortest paths

A Lovász extension is linear on each braid cone `x_{pi(1)} <= ... <= x_{pi(m)}`.
Take

```
d(x) = min(x_1 + x_4, x_2 + x_3) ,
```

which is `Assign_2` under the relabelling `x = (w_11, w_12, w_21, w_22)`, and the
open cone `x_1 < x_2 < x_3 < x_4`. At `x = (0,10,11,12)` the first form is
active, `12 < 21`; at `x' = (0,1,10,20)` the second is, `11 < 20`. Both lie in
the same open cone, so `d` is not linear there.

Two consequences, both worth stating in the paper.

1. **A single compiler call cannot compute the assignment value.** The target is
   not braid-compatible. The construction therefore has to compose many
   threshold integrals, which is what the schedule does. This answers a question
   the current text leaves open for the reader.
2. **The Section 7 problem about shortest alternating distances is a no-go for
   the compiler, not merely a circularity.** The same witness shows shortest
   path lengths are not braid-compatible. The earlier diagnosis, that computing
   `d_i` is a minimum-cost matching computation, is correct but softer. The
   sharp statement is that bottleneck data lives on the braid arrangement
   `x_e = x_f`, and path sums live on the finer arrangement
   `sum_{e in P} x_e = sum_{e in Q} x_e`. No reorganization of threshold graphs,
   `S`, `T` or a Dulmage-Mendelsohn quotient can cross between them.

The right form of the open question is therefore not "can shortest distances be
compiled" but **"is there a canonical fan finer than the braid fan on which a
vanishing-margin compilation still works"**.

The principle that the current compiler obeys and that a finer one must also
obey: *a discontinuous discrete choice may enter a continuous signed circuit
without branching exactly when the real quantity it gates vanishes on every
switching wall of that choice.* The gap `Delta_k` does; a path sum does not.

## 7. `r+1` rounds are tight for `U_r`

Verified end to end on the family the user proposed. Vertices
`L_0..L_r`, `R_0..R_r`, so `n = r+1`. Zero edges `(L_i,R_i)` for `i=1..r`, chain
edges `e_i = (L_{i-1},R_i)` with `D = i` for `i=1..r`, and
`e_{r+1} = (L_r,R_0)` with `D = r+1`.

The unique perfect matching is the chain, forced because `L_0` has only `e_1`, so
`tau = r+1`. An `r`-matching avoiding `L_k` must cover `L_0,...,L_{k-1}` through
the chain and the rest through zero edges, giving `lambda_{L_k} = k`. Hence
`a_{L_k} = r+1-k`. For `j >= 1`,
`mu_{R_j} = min( max(lambda_{L_j},0), max(lambda_{L_{j-1}}, j) ) = j`, so
`c_{R_j} = r+1-j`, and `mu_{R_0} = r+1` so `c_{R_0} = 0`.

One update then gives, exactly:

```
(L_i,R_i):   0 - (r+1-i) + (r+1-i) = 0          zero edges stay zero
e_i:         i - (r+2-i) + (r+1-i) = i-1        every chain slack drops by one
e_{r+1}:     (r+1) - 1 + 0 = r                  likewise
```

so only `e_1` becomes zero, the rank stays `r`, and `S` grows by one vertex. The
state after one update is the same family with `r` decreased, `tau = r`,
`lambda_{L_k} = max(0,k-1)`, which I checked directly. After `r` updates
`S = {L_0,...,L_r}` with the rank still `r`, and only the `(r+1)`-st makes
`e_{r+1}` zero and the chain augmenting.

So `r+1` applications are worst-case necessary for `U_r`, and no sharper
analysis of the same recurrence removes the `O(n^2)` schedule.

## 8. Binary Horner replaces the unary corollary

`cor:integer-observable` currently costs a factor equal to the value range. It
should cost a factor equal to the **bit length**. If one Boolean circuit of size
`s` outputs the `L` bits `b_0,...,b_{L-1}` of `f(S) >= 0`, lift it at amplitude
`Delta` and run Horner on the lifted bits:

```
y_L = 0 ,    y_j = y_{j+1} + y_{j+1} + Delta b_j  for j = L-1 down to 0 ,
```

giving `y_0 = Delta * f(S)` in `O(L)` gates, and `y_0 = 0` when `Delta = 0`
because every `Delta b_j` is then `0`. A signed-valued observable is handled as
a difference of two nonnegative ones.

So the corollary becomes: size `O(ms + mL + m^2 + m log^2 m)`, Lipschitz constant
`max |f|`. This turns the theorem from a statement about predicates into one
about genuine discrete observers, and the rank and reachability data of
Section 4 are inside it.

### 11.1 The two defects, fixed

**Proposition 4.8(1) had a real proof gap.** The old argument said two
unique-optimum chambers have intersecting closures because a path between them
crosses the set where the two costs agree; a third matching can be strictly
better at that crossing. Replaced by an explicit line segment through two
adjacent Birkhoff vertices: `W^0` is `0` on `M_0 u M_1` and `1` elsewhere, `V` is
`+1` on `M_0 \ M_1` and `-1` on `M_1 \ M_0`. Exactly two zero-cost perfect
matchings exist, every perfect matching meets the support of `V` in at most two
edges, so for `0 < s < 1/4` the optimum is uniquely `M_1` at `W^0 + sV` and
uniquely `M_0` at `W^0 - sV`. Shorter than the old text and correct.

**Problem 7.2 was already answered by Theorem 1.2.** Fixed-cardinality matching
reduces to perfect matching by adjoining `n-k` vertices to each side, joining the
new left vertices to `R` and the new right ones to `L` at cost `0`, and leaving
the two new sides unjoined; a counting argument forces exactly `k` original
edges. So `delta` and every `d_i` already have polynomial-size circuits, and the
old open problem was false as stated. Rewritten as a discussion plus a sharper
problem about a direct realization, with the compiler route ruled out by the
non-braid witness.
